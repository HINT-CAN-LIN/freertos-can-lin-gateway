핵심 결론
CAN 메시지와 신호 구현은 시작할 수 있습니다. LIN Routing, Fault 이벤트 손실 정책, QueueUsage 임계값, Speed 산출 모델은 펌웨어 코드에 고정하기 전에 담당자 간 확정이 필요합니다.
1 검토 요약
본 보고서는 CAN_DB_펌웨어 전 최종본_v0.1.dbc를 펌웨어 구현 기준으로 정리한 문서입니다. DBC에는 5개 Node, 6개 Message, 24개 Signal, 18개 Value Table이 정의되어 있습니다. Message ID와 DLC는 모두 유일하며, 5개 주기 메시지와 1개 이벤트 메시지의 전송 정책이 구분되어 있습니다.
펌웨어 착수 판정은 가능하지만 Interface Freeze 완료 판정은 아닙니다. DBC 주석이 명시한 것처럼 LIN routing과 schedule, Fault event retry/loss 정책은 CAN DBC의 범위 밖입니다. 해당 항목은 Gateway 및 LIN 담당자와의 상대 담당자 리뷰 필요 항목입니다.

5.1 CAN Codec 구현 규칙
DBC의 @1+ 표기대로 Intel little-endian, unsigned raw value 기준으로 pack/unpack 구현
수신 시 raw -> physical 변환 후 invalid raw, reserved raw, 범위 초과를 먼저 분리. invalid를 정상값으로 clamp하지 않음
송신 시 physical -> raw 변환 후 반올림 규칙과 범위 검사를 공통 함수로 통일. Torque 계열은 factor 0.1, Speed는 factor 0.1 적용
Enum은 Value Table의 정상값만 application state로 변환. GEAR raw 4..6과 7은 정상 주행 상태로 처리하지 않음
DBC 정의값과 firmware constant의 단일 소스를 유지. 수동 상수 복사는 최소화하고 codec test vector를 함께 관리
physical = raw * factor + offset
raw = (physical - offset) / factor
expected_alive = (previous_alive + 1) % 16

5.4 Fault Manager 구현
Fault_Status는 상태를 주기적으로 덤프하는 메시지가 아니라 Fault transition 이벤트를 전달하는 메시지입니다. Fault Manager는 fault source를 내부 상태로 관리하고, ACTIVE 또는 CLEARED 전이마다 FaultCode, ECUOffline, RecoveryState, SystemState를 채워 Cluster와 PC_TOOL로 전달해야 합니다.
VCU_TIMEOUT: 0x100 age >30 ms, Motor local fail-safe torque action, Gateway Fault_Status 전파
ALIVE_ERROR: counter discontinuity evidence 저장. 중복 frame, skip, missing을 구분 가능하게 로그화
ECU_OFFLINE 계열: ECUOffline enum과 FaultCode 조합을 사용하고, LIN offline은 LIN policy와 일치시킴
동시 Fault는 하나의 frame에 합쳐 임의로 덮어쓰지 않고 transition별 event로 처리. 순서, retry, loss handling은 별도 정책으로 확정
외부 Fault 전파가 빠진 구현은 완료로 판정하지 않음

부록 A 현재 DBC 검증 요약
본 요약은 DBC 텍스트를 기준으로 수행한 정적 검토 결과입니다. CANdb++ 실행 검증과 실제 버스 측정값은 펌웨어/도구 환경에서 별도로 기록해야 합니다.

리뷰 필요
부록 B 펌웨어 구현 체크 순서
1. Interface Freeze 전 결정사항의 담당자 승인 상태 확인
2. CAN peripheral과 RX/TX queue를 먼저 bring-up
3. DBC codec golden vector를 통과시킨 뒤 주기 송신 연결
4. Alive Counter와 VCU timeout을 Motor/Gateway에 연결
5. Gateway의 Vehicle/Body/Gateway Status를 source trace와 함께 구현
6. LIN schedule/routing을 반영하고 Body_Status consistency 검증
7. Fault Manager와 Cluster/PC_TOOL 외부 전파 검증
8. 실제 cycle, jitter, queue, fault latency를 측정해 DoD evidence 작성
최종 판정 
현재 DBC는 펌웨어 구현을 시작할 수 있는 기준입니다. 구현 완료 판정은 DBC 로딩만으로 충족되지 않으며, 테스트 증적과 상대 담당자 리뷰, Fault 외부 전파, LIN routing 확정을 포함한 DoD를 모두 만족해야 합니다.
