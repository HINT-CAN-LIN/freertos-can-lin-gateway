2. System Context
System Context에서는 외부 Actor와 지원 장비의 관계를 정의하고, ECU 내부 핀맵이나 PWM 같은 상세 구현은 다루지 않습니다. Physical
Device는 시스템 내부 ECU가 직접 제어하는 계층으로 표현합니다.
                         Driver / User
                       /              \
              control input          status display
                    /                    \
                   v                      ^
        +------------------------------------------+
        |       FreeRTOS CAN-LIN System           |
        |  VCU / Motor / Gateway / Cluster        |
        |  Door / Light / Window / PC Tool        |
        +-------------------+----------------------+
                            |
                 CANable <-> CAN Network
                   (external interface)
Test / Diagnostic Engineer -> PC Diagnostic Tool
PC Diagnostic Tool -> CANable -> CAN Network -> ECU System

2.2 Context Boundary Rules
- CANable은 시스템과 CAN Network 사이를 연결하는 외부 COTS 장비이며 자체 개발 대상이 아님.
- ST-LINK, SavvyCAN, USB Logic Analyzer, PulseView, STM32CubeMX/CubeIDE는 개발 또는 검증 지원 도구로 관리함.
- PC Diagnostic Tool은 직접 개발하고 Test Evidence에 포함하므로 System Scope 내부 요소로 관리함.
- Motor Driver, DC Motor, Door Actuator, LED/Lamp, ST7796S TFT, Window H-Bridge/Motor/Switch는 해당 ECU 아래 Physical
Device 계층으로 관리함.

Detection -> State -> Action -> Propagation -> Recovery

  -> Fault_Status / Gateway_Status -> Cluster + PC

  Local safety input -> local condition -> unsafe output inhibition
  -> safe output -> local recovery
No external Fault propagation means Fault handling is not Done.
