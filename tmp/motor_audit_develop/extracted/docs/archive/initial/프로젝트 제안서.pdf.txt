01  왜 이 프로젝트인가?
목표는 “여러 기술을 얹은 작품”이 아니라, 실제 차량 네트워크의 역할 분리와 통합 과정을 경험하는 것입니다.
한 줄 목표  |  CAN 기반 주요 ECU 와 LIN 기반 바디 ECU 를 Gateway ECU 가 연결하고, FreeRTOS 로 실시
간 통신·라우팅·진단을 안정적으로 처리한다.
프로젝트에서 얻고 싶은 경험
● STM32 에서 CAN·UART/LIN·Timer·GPIO 등 주변장치를 직접 다루는 펌웨어 개발 경험
● FreeRTOS 의 Task, Queue, Mutex, Task Notification 등을 실제 필요에 따라 적용하는 경험
● 여러 ECU 가 각자 역할을 맡고 통신 규격에 맞춰 동작하는 분산 임베디드 시스템 통합 경험
● Timeout, Alive Counter, Checksum, Node Offline 등 정상 동작 외의 오류 상황까지 설계·검증하는 경험
● DBC, LIN Schedule, Routing Table, Test Case 등 “코드 밖의 설계 산출물”까지 남기는 경험
왜 포트폴리오에 유리한가
흔한 프로젝트 이번 프로젝트에서 보여줄 것
단순 CAN 실습 CAN ↔ LIN 간 메시지 변환·주기 차이·라우팅 정책까지 설명 가능
단일 MCU 작품 VCU / Motor / Cluster / Gateway / Door / Light ECU 의 역할과 인터페이스를 구분
RTOS 사용 경험 ISR → Queue → Task 구조, 우선순위와 Queue Overload 를 실제 문제와 연결
정상 동작 데모 통신 단절·체크섬 오류·노드 탈락 등 Fault 시나리오와 Fail-safe 까지 검증
성공 기준: “기능 개수”보다 CAN-LIN Gateway 의 핵심 경로가 안정적으로 동작하고, 왜 그렇게 설계했는지 팀원 모두가 
설명할 수 있는 상태.

02  전체 시스템 구조
CAN 은 주요 차량 상태·제어, LIN 은 Door/Light 같은 저속 바디 전장, Gateway 는 두 네트워크의 연결점입니다.
기본 ECU 역할
ECU 핵심 역할
VCU ECU Gear / Brake / Accelerator 입력, Vehicle State, 주요 CAN 상태 송신
Gateway ECU CAN↔LIN Routing, Signal Cache, Rate Conversion, 통신 상태 감시, 진단
Door ECU LIN Slave, Door Open/Close·Lock 상태 및 명령 처리
Light ECU LIN Slave, Head/Reverse/Turn/Hazard Lamp 상태 및 출력
Motor ECU · 확장 Torque Request 수신, PWM/Encoder, RPM·Fault 송신
Cluster ECU · 확장 Speed / RPM / Gear / Door / Warning 표시
MVP 는 VCU → CAN → Gateway → LIN → Door/Light 의 4~5 노드 구성으로 시작하고, 안정화 후 
Motor/Cluster ECU 를 붙입니다.

03  Gateway ECU + FreeRTOS 설계
FreeRTOS 는 “썼다”가 아니라, 서로 다른 통신과 주기 작업을 안전하게 분리하기 위해 사용합니다.
Gateway 가 실제로 해결해야 하는 문제
문제 설계 방향
주기 차이 예: CAN Speed 10ms → 최신값 Cache → LIN 100ms Schedule 에 맞춰 전달
동시 처리 CAN 수신, LIN Scheduler, Routing, 진단, Logging 이 동시에 돌아감
ISR 부담 ISR 에서는 Frame 을 Queue 로 넘기고 빠르게 종료, Decode/Route 는 Task 에서 처리
오류 감지 CAN/LIN Timeout, Alive Counter, Checksum, Node Offline, Queue Overflow 감지
확장성 if 문 나열 대신 Routing Table / LIN Schedule 을 설정값으로 분리
면접에서 설명할 핵심: “10ms CAN 메시지를 왜 100ms LIN 으로 그대로 전달하지 않았는가?”, “ISR 에서 왜 Routing 까
지 하지 않았는가?”, “노드가 멈췄을 때 어떻게 검출했는가?”

04  주요 기능과 시연 시나리오
완성 후에는 버튼 몇 번과 케이블 한 번만 뽑아도 프로젝트의 핵심이 눈에 보이도록 구성합니다.
핵심 기능
기능 구현 예
CAN → LIN Routing VCU 의 Gear/Speed/State 를 Gateway 가 받아 Door/Light 명령으로 변환
LIN → CAN Routing DoorStatus/LightStatus 를 Gateway 가 CAN 메시지로 재구성
LIN Schedule Gateway 가 LIN Master 로서 Door/Light Frame 을 주기적으로 요청·송신
Network Health Heartbeat/Timeout/Alive Counter 로 ECU ONLINE/OFFLINE 판단
Fault Injection PC Tool 에서 Timeout/Checksum/CAN Flood 등을 의도적으로 발생
Logging CAN/LIN/Gateway 상태를 시간순으로 기록하고 테스트 결과 저장
대표 데모 3 개
01  자동 Door Lock
Speed > 20 km/h
→ CAN 수신
→ Gateway 판단
→ LIN Door Lock
→ DoorStatus CAN 복귀
02  Gear R 후진등
Gear = R
→ VCU CAN
→ Gateway Route
→ LIN Light ECU
→ Reverse LED ON
03  Door ECU 탈락
Door ECU 전원 제거
→ LIN Timeout
→ Gateway Fault
→ CAN 경고
→ GUI OFFLINE
MVP 시연은 모터가 없어도 충분합니다. 통신 경로와 오류 처리부터 완성한 뒤 Motor/Cluster 를 확장합니다.
