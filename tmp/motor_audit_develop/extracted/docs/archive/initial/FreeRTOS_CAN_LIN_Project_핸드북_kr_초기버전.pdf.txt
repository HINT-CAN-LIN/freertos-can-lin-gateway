1. 프로젝트 개요와 최종 아키텍처 
이 프로젝트는 차량 제어 영역을 CAN, 차체·바디 영역을 LIN 으로 나누고, FreeRTOS 기반 Gateway ECU 가 두 
네트워크 사이의 Signal Routing, 주기 변환, 상태 감시, Fault Handling 을 수행하는 분산 전장 시스템을 
만드는 7 인 팀 프로젝트다. 
핵심 목표 
단순한 CAN/LIN 송수신 데모가 아니라, 요구사항 -> Interface Definition -> Firmware -> PC Diagnostic -> Automated 
Test -> HW Evidence 까지 하나의 재현 가능한 개발 흐름을 완성한다. 
1.1 목표와 성공 기준 
• CAN 500 kbps 에서 VCU, Motor ECU, Gateway ECU, Cluster ECU 가 정해진 Message/Signal 을 주고받는다. 
• LIN 19.2 kbps 에서 Gateway 가 LIN Master 로 Door ECU 와 Light ECU 를 Schedule 에 따라 Polling 한다. 
• Gateway 가 CAN Signal 을 해석해 LIN Frame 으로 변환하고, LIN 상태를 CAN 상태 메시지로 변환한다. 
• CAN timeout, LIN timeout, Alive Counter 오류, ECU offline 을 감지하고 Cluster 와 PC Tool 에 전달한다. 
• PC Diagnostic Tool 에서 DBC decode, raw monitor, ECU health, Logging, Fault Injection, Test 
Automation 이 가능하다. 
• 모든 기능은 Jira Issue, Git Branch, Commit, PR, HW Test Evidence 로 추적된다. 
1.2 범위와 명시적 제외 
표 1-1. 프로젝트 범위 기준 
구분 프로젝트 기준 
포함 
CAN/LIN Interface 설계, FreeRTOS Gateway, 4 개 CAN ECU, 2 개 LIN ECU, PC Diagnostic 
Tool, Fault Handling, pytest 기반 자동화 
기본안 
Motor ECU 는 실제 모터를 필수로 연결하지 않고 Virtual Motor 모델로 동작한다. Torque 
Request 가 Target RPM 과 RPM 응답으로 변환된다. 
선택 확장 
실제 모터·인버터 연결, LDF 자동생성, CAN FD, 정식 차량 진단 프로토콜, HIL 장비 연동은 Stretch 
Goal 로 분리한다. 
제외 
양산 수준 기능안전 인증, 실제 차량 장착, 고전압 전력부 설계, 상용 진단 규격 전체 구현은 본 MVP 
범위에 포함하지 않는다.

5. CAN 설계, CANdb++, DBC 검증 
CAN Interface 는 Excel 에서 논의할 수 있어야 하고, CANdb++에서 Node/Message/Signal 의 의미를 확정한 
뒤 vehicle.dbc 로 배포한다. DBC 가 만들어졌다고 끝이 아니며, cantools 로 Parse 와 Encode/Decode 를 
반복 검증한다. 
5.1 CAN Matrix 기본 규칙 
• Message ID 는 프로젝트 전체에서 중복되지 않아야 하며, 확장 ID 사용 여부를 명시한다. 
• 주기 Message 는 10 ms, 20 ms, 100 ms 등 주기를 고정하고 event Message 는 발생 조건과 재전송 정책을 
적는다. 
• 모든 Signal 은 Start Bit, Length, Byte Order, Factor, Offset, Min, Max, Unit, Initial, Invalid 를 갖는다. 
• Sender 와 Receiver 를 모두 적고, 수신 ECU 가 timeout 과 invalid 를 어떻게 처리할지 별도로 정의한다. 
• Alive Counter 는 4 bit, 0-15 순환으로 통일하고 전송 Message 에 포함할지 규칙을 고정한다.

코드 10-1. Fault Injection 예시 
def inject_vcu_timeout(bus, duration_ms=50): 
    # Do not send VCU_Command for longer than 30 ms. 
    wait_ms(duration_ms) 
 
def inject_alive_error(bus): 
    send_vcu_command(bus, gear="D", alive=7) 
    send_vcu_command(bus, gear="D", alive=12)  # discontinuity 
 
def inject_door_offline(bus): 
    # Stop Door ECU response for 3 Door_Status cycles. 
    stop_lin_response("Door ECU") 
    wait_ms(300) 
    assert_can_fault("DOOR_ECU_OFFLINE")
